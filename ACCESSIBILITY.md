# Accessibility

WP Citizen aims to make its products and documentation usable by as many people as possible, including people who use assistive technologies or alternative input methods.

When building or reviewing a feature, consider:

- Semantic HTML and accessible names for controls.
- Full keyboard operation, logical focus order, and visible focus indicators.
- Screen-reader announcements for dynamic status, validation, and errors.
- Sufficient text and interface contrast; do not rely on color alone.
- Zoom, responsive reflow, reduced motion, and readable typography.
- Accessible labels, instructions, and error recovery in forms.
- WordPress admin and frontend conventions, including compatibility with common assistive technology workflows.

## Reporting an accessibility barrier

Open an issue in the affected repository and select the closest issue type. Describe the task that became difficult, the expected behavior, the actual barrier, and assistive technology/browser details when you can share them. Avoid sharing personal or sensitive information.

Accessibility improvements are welcome as focused bug reports, design feedback, tests, or pull requests.
